Green Miles Travel Website: Project Documentation
Version 1.0 · October 22, 2026 · Visual reference: Luxtrail (Webflow) · Brand: Green Miles Travel
0. How to use this document
This document is written to be handed to a developer, or to a coding assistant together with your Instagram images, and produce the full site. Part 1 says what to build, Part 2 says how it looks and moves, Part 3 says how to build it, Part 4 says how to protect it. Part 5 is the launch checklist and Part 6 explains how to feed all of it, plus the photos, to a coding tool. Build in the order given in section 3.12.
On “exactly like Luxtrail.” Luxtrail is a paid Webflow template. Its layout, section order, interaction patterns and responsive behavior are the reference, and this document asks you to match them closely. Its photos, illustrations, icons, copy and exported code belong to the template’s author and are licensed to the buyer for one site. Do not copy them. Every image, drawing and sentence on the Green Miles site should be original or come from Green Miles itself. That is also what stops the site from reading as a re-skinned template.
Part 1. Product Requirements (PRD)
1.1 Business context
Green Miles Travel is a small travel, trekking and guiding company built around the raw side of North-East India, with budget-friendly trips as its main promise. Today it lives on Instagram (greenmiles_travels) and runs on phone and WhatsApp enquiries. Its Instagram highlights show current trips to Dzukou, Kapamodzu and Khonoma in Nagaland.
The website replaces “DM us for details” with a place where a visitor can see real photos, read exactly what a trip includes, and send an enquiry. It also gives the owner a panel to run all of that without a developer.
The logo carries a tagline about journeys with a positive impact. Confirm its exact wording with the client before using it in any copy.

Part 2. Design Specification
2.1 Rules that keep it from looking generated
1. Real photography only, from Green Miles trips. No stock photos, no generated images.
2. No dotted grids or dot patterns, no sparkles, no glow or blur blobs, no purple-to-blue gradients, no glass panels.
3. One decorative language, drawn once as SVG and reused: torn paper edges, a hand-drawn dashed trail line, trail-marker stamps, and the leaf and plane from the logo. All of it is original, not traced from Luxtrail.
4. An uneven, human rhythm: cards tilt 1 to 3 degrees in fixed patterns, photos carry paper-tape strips, grids are not perfectly uniform.
5. No emoji as icons. One outline icon set (Lucide, stroke 1.75) used everywhere.
6. Copy is specific: real place names, altitudes, distances, inclusions. See 2.11 for words to avoid.
7. Every number on the site is true. A counter stays hidden until there is real data behind it.
8. The only overlay on photos is a flat dark tint for legibility. No gradient washes.

Motion is attribute-driven. Add data-reveal to any element in the Blade views and one module animates it, so no section needs its own script.
import gsap from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
import { SplitText } from 'gsap/SplitText';
gsap.registerPlugin(ScrollTrigger, SplitText);

const mm = gsap.matchMedia();
mm.add('(prefers-reduced-motion: no-preference)', () => {
  document.querySelectorAll('[data-reveal=heading]').forEach((el) => {
    const split = SplitText.create(el, { type: 'lines', mask: 'lines' });
    gsap.from(split.lines, {
      yPercent: 110, duration: 0.9, ease: 'power3.out', stagger: 0.08,
      scrollTrigger: { trigger: el, start: 'top 85%', once: true },
    });
  });

  document.querySelectorAll('[data-digit]').forEach((col) => {
    const digit = Number(col.dataset.digit);
    gsap.to(col.firstElementChild, {
      yPercent: -10 * digit, duration: 1.6, ease: 'power3.inOut',
      scrollTrigger: { trigger: col, start: 'top 85%', once: true },
    });
  });
});
For the odometer, each digit is a clipped box one digit tall containing a stack of ten cells, 0 to 9. Check the SplitText options against the current GSAP docs when you wire it in.
Layout details that avoid common bugs: give every image width and height or an aspect-ratio box to prevent layout shift; set the hero image to fetchpriority high and preload it; lazy-load everything below the first screen; keep tilt rotations on an inner wrapper so hover transforms do not fight them.

3.8 Enquiry flow
1. Visitor submits the form on /contact or from a trip page (trip preselected).
2. Server validates, checks the honeypot and Turnstile token, saves the enquiry with a consent timestamp.
3. A queued email goes to the business address; an optional confirmation goes to the visitor if they gave an email.
4. The success screen shows a WhatsApp button that opens wa.me with a prefilled message that names the trip and dates.
5. The admin sees it in the Enquiries inbox with status New.
6. Call and WhatsApp taps from any page fire analytics events.

4.2 Privacy and personal data

Rule

4.3 Pre-launch security checklist
1. APP_DEBUG is false and APP_ENV is production.
2. Admin Owner has 2FA on, and the default or seeded passwords are gone.
3. Policy tests pass: an Editor gets a 403 on users, roles and settings, by URL as well as by menu.
4. A real attempt to upload a PHP file, an SVG with a script and an oversized image is rejected.
5. A script tag pasted into the rich editor and into every form field is shown as text or removed.
6. Form rate limit and Turnstile verified from outside the office network.
7. Security headers and CSP verified with an online scanner; no console CSP errors on any page.
8. Database and .env are unreachable from the web; directory listing is off.
9. A backup was restored to a clean machine and the site came up.
10. Staging is noindex and password-protected, and production is not.
11. Registrar, hosting, Cloudflare, mail and analytics accounts are owned by the client with 2FA on.
